# 整体匹配：产品卖点与视觉风格分开评分

本次沿用“硬筛选 → 整体排序 → 入选整体内匹配组件”的流程，只修改整体排序和结果解释，不重新生成第二阶段向量，不引入付费API。

## 两路分数

1. 产品卖点：product_description + selling_points + retrieval_terms，不拼接style。用同一模型的查询向量对照第二阶段整体叙述向量。整体叙述本身仍包含视觉信息，这不是去除了所有风格影响的纯产品模型。
2. 视觉风格：只编码style，分别对照每套Listing中合格图片的既有描述向量，取最高3张的余弦相似度均值。图片必须在活动索引内、身份为current_or_family，且允许检索与生成参考；文字、视频和禁用图片不参与风格评分。命中图片及分数保存为style_evidence。
3. 产品卖点分先达到minimum_similarity，才计算综合排序分。综合分默认=0.65×产品卖点分+0.35×视觉风格分，然后取whole_top_k套。后续组件用途排序规则保持原实现。

风格不是硬条件；高风格分也不能使不相关产品越过产品相似度门槛。没有填写style或没有合格图片时，退回100%产品卖点分，style_similarity=null，style_status明确记录原因，不伪造风格分。

## 配置

config/runtime.json → retrieval：

```json
{
  "whole_score_weights": {"product": 0.65, "style": 0.35},
  "style_evidence_top_n": 3
}
```

两项权重均须有限且非负，product必须大于0；程序自动归一化。style_evidence_top_n为正整数。65/35是可调整的初始值，尚未通过人工标注集校准；不要为了某一商品必进第一而调整。

如视觉方向比产品颜色更重要，可在固定测试集上比较其他权重。retrieval_terms属于产品查询，风格词应填style。

## 输出字段

- product_query / style_query：实际两路查询文字。
- whole_scoring：配置权重、风格证据数量及产品门槛。
- whole_candidates[].product_similarity：产品卖点余弦分。
- style_similarity：最接近的图片描述风格余弦分均值。
- relevance_score：最终综合排序分；为兼容旧读取程序，整体similarity字段也保存此综合分，已不再是单个向量的余弦分。
- weights：该候选实际使用的权重；缺风格时为1/0。
- style_status / style_evidence：风格状态及可追溯原图、描述、组件ID与来源。

组件similarity仍是原始余弦分；组件relevance_score仍是原有用途标签加权分。不能跨版本直接比较整体旧分数与新综合分数，不能将分数当作质量、概率或销量。

## 真实样例与验证

50套库重跑12个输入，输出在outputs/split-scoring-20261103，不覆盖原始测试结果。深色酒店风的第2号商品由原整体排序第6进入第3：产品分0.699311、风格分0.648413、综合分0.681497。当前前三为18、38、2；第2号在这三套中风格分最高，但产品匹配分较低，因此不强制第一。

16项单元测试通过，包含风格重排、产品门槛、禁用图片、无风格回退及错误配置。12个真实案例已重跑，检查组件均来自所选整体、无对应国家返回空、仍禁止自动进入生成。soft-fit只改组件用途，其整体选择与soft-quilt一致。

## 当前限制

视觉分基于GPT既有图片描述的文本向量，不会在每次检索时重新看原图，不是原生视觉嵌入或视觉模型复核。部分批量描述较笼统，不能准确区分暗色酒店、普通卧室及豪华程度；65/35也不保证最符合人工审美。可以按证据图人工核对，后续丰富颜色、光线、场景与风格描述或接视觉复核API。整体进入候选不代表它的所有组件都满足风格；具体组件仍同时受到用户用途的影响。

默认config/runtime.json继续指向前五套库。此次50套实测使用outputs/split-scoring-20261103/runtime.json，运行时须显式传入该配置。
