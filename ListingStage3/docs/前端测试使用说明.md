# 本机匹配测试前端

在 PowerShell 运行：

```powershell
cd D:\ListingStage3
./run_web.ps1
```

打开 http://127.0.0.1:8765 。不要直接双击 web/index.html，该页面需要 Python 接口读取真实特征库。

## 测试步骤

1. 填写核心卖点，每行一项，例如 `soft`、`lightweight`。产品描述、国家、品类、站点、风格均可留空，不自动添加默认描述。
2. 展开筛选设置，可调整候选数量 1–50；可关闭接近分数的历史采集顺序调整，查看严格相似度排序。
3. 点击寻找整体参考。分数来自当前第三阶段匹配代码，不是模拟结果；综合分不是质量分或满足率。
4. 打开候选，切换整体特征、图片、视频、文字和来源版本。每项整体特征的证据按钮能跳转到对应原始组件。
5. 导出结果 JSON，记录本次请求、实际设置和候选包。导出文件只保留引用，不打包图片或视频。

浏览全库按历史采集编号显示 50 套素材。没有下载的视频不会补造；下载的视频由本地接口提供，支持范围读取与拖动播放。

## 当前限制

- 当前模式为向量匹配，尚未开发 LLM 条件复核与候选重排。
- 保留“先选整体”的原则。页面组件展示仅供核对，不代表已选作生成参考。
- 当前 Nomic 对部分中文输入适配不足，建议先用英文控制变量测试。
- 浏览库不要求 Ollama 在线；点击匹配时需要本地 Ollama 与已建库模型摘要一致。
- 服务只监听 127.0.0.1；同事在其他电脑不能使用你电脑的 localhost 地址。GitHub 源码也不包含当前 50 套媒体与向量数据库。
- 前端输入和结果只在当前页面内存中保存；刷新后重新输入。原始素材与特征库不会被页面修改。

## 文件

- `web/index.html`：页面结构与输入表单。
- `web/style.css`：布局与响应式样式。
- `web/app.js`：请求提交、结果展示、整体详情、证据跳转和 JSON 导出。
- `src/listing_stage3/web.py`：本机 HTTP 接口，加载现有库并调用 matcher；仅允许已登记的媒体编号，支持视频 Range。
- `run_web.ps1`：启动脚本，优先复用相邻 ListingStage2/.venv。
- `tests/test_web.py`：视频范围读取、路径限制、Host/Origin 与 JSON 请求测试。

停止服务：在启动窗口按 Ctrl+C。模型或配置故障会显示明确错误，不会伪造候选。
