# 多网址配置与素材关联

更新日期：2026-11-02。沿用第一阶段采集、第二阶段分析流程。

## 配置多个入口

只需编辑 `config/sources.json` 一个文件，无需再为每个网址创建 JSON。结构为：

- `defaults`：公共采集参数。
- `sources`：网址列表，每项填写 id、url、marketplace、language、category_node、category_name、description，可附 country、tags 和 enabled。
- 单个来源可直接填写 max_products、max_images_per_product 等覆盖公共参数；合并顺序是程序默认值 → defaults → 单个来源。列表字段整体覆盖，不追加。

示例（第二个来源仅示范停用状态，正式启用前需填完整真实网址和类目信息）：

```json
{
  "schema_version": 1,
  "defaults": {"max_products": 50, "max_images_per_product": 4, "max_videos_per_product": 0, "request_delay_seconds": 3},
  "sources": [
    {"id": "amazon-us-topper-bsr", "enabled": true,
     "url": "https://www.amazon.com/gp/bestsellers/home-garden/8521807011",
     "marketplace": "US", "language": "en-US",
     "category_node": "8521807011", "category_name": "Mattress Toppers",
     "description": "美国 Topper BSR 前50"},
    {"id": "another-source", "enabled": false, "description": "待补充的第二个网址"}
  ]
}
```

id 必须唯一；不要随意改已使用的 id，以便保留来源历史。仅改单个网址的采集数量时，在该项内添加 `"max_products": 10`。当前保留图片上限 4、视频上限 0 的既有预算，避免格式迁移扩大采集量。

更细参数如 page_timeout_ms、max_aplus_images_per_product、max_image_bytes 也可放 defaults 或来源项；未填写使用程序默认值。旧 topper-us.json 和 config 引用格式保留兼容旧命令，新多来源配置无需维护它们。

alternate_ranking_url 是同来源备用 BSR 入口；discovery_url 当前仅记录、不执行搜索抓取。当前仅可执行美国站 BSR，其他国家可先 enabled=false，启用前仍需解析适配。搜索顺序不能作为 BSR。

以后接 Excel/SQL 时，读取器只需将数据转换成同样的 defaults/sources 字典，调用 `normalize_sources()`；后续校验、采集及归档保持共用。Excel/SQL 读取器尚未实现，本次不引入数据库或表格依赖。

```powershell
Set-Location D:\Crawl4AI
& D:\python\python.exe -m listing_ingest.sources --plan
& D:\python\python.exe -m listing_ingest.sources --source amazon-us-topper-bsr --plan
# 去掉 --plan 才访问网站；可重复 --source 选择多个入口
& D:\python\python.exe -m listing_ingest.sources
```

先完整校验全部选中来源合并后的配置，再按顺序采集。单个来源失败继续后续来源，独立报告保持原格式；总清单写 library/source_batches。当前无定时调度器，频率配置和增量抓取后续另做；这次没有启动整批网络采集。

## 关联方式

每个新导出的商品目录新增 素材关联.json：identity 包括 source_id、marketplace、ASIN、snapshot_id、run_id；texts 保留标题、每条五点、普通详情与 A+ 的独立 ID；media_references 保留图片/视频、资产哈希、来源、主图标记和文件路径；modules 保留 DOM 模块顺序、原文及图片 URL。

同一文件哈希表示资产相同，但不同商品/快照的 reference 不合并。变体仅保留页面可见 variants_observed，当前选中 ASIN 的图文不自动归属于所有变体。视频可能展示系列商品，所属范围还需第二阶段复核。

模块图片与文字通过网页 DOM 明确关联；五点与图片共享商品和快照，不能按序号强行一一对应。semantic_links 当前为空，第二阶段后续按卖点主题生成多对多关系：text_id、reference_id、关系类型、理由、置信度、证据及审核版本。一个卖点可对应多张图片或视频片段，一张图也可表达多个卖点。

第一阶段只保存可观察的结构关系；第二阶段负责语义判断、归属复核。新文件不改写既有报告或冻结样本；已有报告可只读生成关联试验包，未导出媒体时 export_path 允许为空。

## 第二阶段接入计划

通用导入器优先读取 素材关联.json，保留这些 ID；特征、向量、分组均绑定 snapshot 和素材/文本 ID。缺少关联文件时使用旧 report 兼容解析。当前第二阶段仍是固定五商品试验，尚未自动加载这个新增文件。后续将 semantic_links 存关系库，人工修改后使依赖分析版本失效。


## 网站与品类目录（2026-11-02 已实现）

每项来源现在可以配置 country_code、site_id、category_id，例如 US、amazon、toppers。marketplace 仍表示平台站点；category_node/category_name 保留网站原始类目，category_id 为跨网站统一的内部品类。路径标识使用英文字母、数字、下划线或连字符，不能使用路径分隔符、中文或 Windows 保留名称；展示说明仍可填写中文。

新输出路径：`library/products/US/amazon/toppers/商品编号/采集批次/`。目录内仍包含完整图文、视频、详情及素材关联。原始媒体继续保存在 objects 中按哈希管理。

旧来源若未填这些字段，美国 Topper 自动兼容为 US/amazon/toppers；其他旧亚马逊节点默认使用 node-节点号，建议显式填写内部 category_id。不得凭网页标题猜业务品类。目录使用 report.run_id 作为批次，商品 snapshot_id 保存在结构化文件中。

catalog.py 提供通用商品标识：亚马逊要求已确认 ASIN；独立站标准化数据优先使用 parsed.product_id，没有时按原始 HTTPS requested_url 生成稳定哈希编号。链接参数不同可能产生不同编号，未来站点适配器应优先提取站内 ID 或可靠规范链接。通用导出已可处理标准化独立站商品数据，但当前真实网络采集仍只支持美国亚马逊；不能配置一个独立站网址就直接爬取。

商品信息、来源与排名、素材关联及批次索引已增加 country_code、site_id、category_id、product_id 字段；素材关联 schema_version 更新为 2。完整业务标识需组合国家、网站和商品编号，避免跨网站碰撞。品类是组织属性，同一商品出现在不同品类时仍通过商品标识区分引用。

已从冻结报告重新导出 50 个商品至 US/amazon/toppers，未重新联网。旧商品目录保留，原始报告的旧 product_exports 路径仍有效；批次浏览索引改为新目录，旧索引备份及迁移清单在 library/layout_migrations。第二阶段固定样本依赖的旧路径继续可用。
