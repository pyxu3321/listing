# 人工 GPT 分析规范（目标协议）

本协议描述接下来处理新批次的方法；当前仅复用旧试验 gpt_features.json，尚无通用导入命令。人工交互记录和未来 API 响应使用同一业务契约。

## 提交给分析者

每个任务提供任务 ID、ASIN/市场、snapshot_id、原图与 reference_id/哈希、来源角色和证据、关联标题/五点/A+ 模块。排名不作为内容评分的提示依据。任务单列出预期图片和文本数量，便于核对漏项。

## 逐项输出

图片：用途、可见主体、构图、配色、场景、文字内容、卖点表达、信息顺序、风格、identity_scope、可借鉴原则、不适用情况、证据与未知项。

文本：原文定位、主题、句式、信息顺序、利益/参数表达、场景和客群、语言风格、来源宣称及限制。

每项带 producer_type=manual_gpt、分析批次、提示词版本、任务关联和 review_status=pending_review。具体模型未知就留 unknown。质量评分无批准标准时保持 null。

## 识别规则

- 只写看见或读到的内容；看不清的字不得猜测。
- 观察、竞品声明、推断分开；推断说明依据与限制。
- 认证标识只能说明图中有该标识，不代表认证已验证。
- A+ 中其他产品或品牌图单独标记，不迁移到当前商品参数。
- 联系表适合整体观察，小字和边界问题回到原图查看。
- 原图原文、分析翻译和结构化总结分别保存。

## 导入与人工复核

规划校验任务数、引用、哈希、字段类型、枚举、重复项和缺失理由。校验失败保留错误，不自动用模型补齐事实。运营修改需记录原因及新版本；批准绑定准确版本。文字特征修改后重算对应向量，相关聚类/评分/原则需重新检查。

暂不把示例 JSON 当成现成 API。目标字段的定义见 [数据契约](data-contract.md)；自动任务组包、导入校验器、审核状态机仍待实现。
