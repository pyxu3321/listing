# 完整原文参与整体编码（v4）

## 本次修正

删除批次装配器中“五点只取前五条、每条前180字符”的逻辑。当前标准build默认使用v4，标题、全部已采集五点、普通详情、A+文字，以及允许纳入整体的既有图片/视频描述进入一个完整证据文档。当前没有执行新的图像识别、OCR、语音转录或LLM卖点归纳。

过去整体摘要可能遗漏来源文字尾部；现在原文声明完整保留，并给每一项绑定组件ID、来源URL和快照。只合并完全相同的证据正文，保留重复来源的所有引用，不按关键词或相似度擅自合并语义。

## 编码方式

完整证据文档 → 连续分块（默认每块最多2000字符） → 使用同一本地模型编码每一块 → 按块实际字符数加权池化并归一化 → 一个整体向量。

2000是单次请求的字符预算，不是截断长度。每块有起止偏移、正文哈希和关联证据段ID，所有块必须拼回原文且全部参与编码。模型请求继续truncate=False，服务拒绝时显式失败，不截断后半段。这是整体文档长输入处理，不是平均旧的图片/五点组件向量；原来的1277个组件向量不变。

v4配方：whole-listing-full-evidence-v4；旧版摘要配方v3仍保留以供对照。第三阶段支持两种配方，但同一次整体排序禁止混用两者。新旧相似度的分布可能变化，阈值和排序需重新校准。

## 运行

```powershell

D:\python\python.exe -m listing_stage2.full_evidence_batch `
  --source D:\ListingStage2\outputs\batches\all50-20261103 `
```

## 验证和边界

第二阶段42项、第三阶段21项单元测试通过；包括180字符以后的独有尾部确实参与、尾部改变影响整体向量、长文连续完整分块、去重仍保留来源、策略排除、旧组件不变、禁止混用新旧配方。新库重跑原12个请求和柔软/轻便请求，检查国家/结构筛选及组件暂缓。

此修复保证输入不被程序固定长度截掉，不保证一个向量能逐项准确匹配所有卖点。本地模型对某些中文短语仍可能区分不足。source_statements是原文声明，不是LLM提炼出的完整标准化卖点词典；归纳、近义表达、复合条件和功效限定的语义判断留给后续LLM或人工。竞品声明仍不构成自有产品事实。
